# 🎨 تصمیم‌های طراحی و معماری — HDKALA (React)

## ۱) چرا React 18 + Vite (و نه Next.js)؟
- این پروژه یک فروشگاه دموی فرانت‌اند است؛ **SEO از نوع SSR** (ایندکس‌شدن صفحات توسط موتور جستجو) هنوز جزو نیازها نیست و داده‌ها mock هستند.
- Vite سبک‌ترین و سریع‌ترین تجربه توسعه را می‌دهد و خروجی build استاتیک دارد که روی هر CDN/هاست ساده (Netlify, Vercel, GitHub Pages) بالا می‌آید.
- اگر بعداً SEO واقعی لازم شد، مهاجرت به Next.js (با Router و state فعلی) کم‌هزینه است.

## ۲) چرا Zustand (به‌جای Context + useReducer)؟
- سبد خرید، علاقه‌مندی، کاربر، سفارش‌ها و تم همگی state سراسری هستند؛ Context + useReducer برای این مقیاس boilerplate زیادی دارد.
- Zustand با middleware رسمی `persist` **ماندگاری localStorage را خودکار** انجام می‌دهد (بخشی از معیارهای پذیرش) و رندرهای اضافی را حذف می‌کند (selector های اتمیک).

## ۳) دیزاین سیستم

### پالت رنگ
| نقش | رنگ | کاربرد |
|-----|-----|--------|
| اصلی (Primary) | ایندیگو `#4f46e5` (طیف 50–950) | دکمه‌ها، لینک‌ها، فوکوس — **ادامه هویت برند نسخه قبلی** |
| مکمل (Accent) | کهربایی `#f59e0b` | نشان تخفیف‌ها، CTA های ویژه |
| موفقیت / خطا | زمردی `#10b981` / رزی `#f43f5e` | استاک، اعتبارسنجی، اعلان‌ها |
| خنثی | Slate (طیف کامل) | پس‌زمینه، متن، حاشیه — روشن `slate-50` / تاریک `slate-950` |

### تایپوگرافی
- **Vazirmatn** (وزن‌های 400/500/600/700) — **لوکال در `public/fonts`** با `@font-face` و `font-display: swap` (بدون وابستگی به CDN، سریع‌تر و سازگار با تحریم).
- سلسله‌مراتب: h1 تا 2xl–5xl extrabold / متن 14–16px / اعداد قیمت همیشه `font-extrabold` + جداکننده هزارگان فارسی (`toLocaleString('fa-IR')`).

### مقیاس فاصله و گوشه و سایه
- شعاع گوشه: `rounded-xl` (کنترل‌ها) و `rounded-2xl` (کارت‌ها) — ظاهر نرم و مدرن.
- سایه: `shadow-card` (نرم) برای کارت‌ها و `shadow-pop` (ایندیگو) برای حالت hover کارت محصول و دکمه‌های اصلی.
- فاصله‌گذاری: شبکه 4px تیلویند + `container-page` (max-w-7xl).

### حالت‌های دکمه
کامپوننت `Button` با ۵ واریانت (primary / accent / outline / ghost / danger)، ۳ سایز، و حالت‌های `hover` (تغییر رنگ + سایه)، `active` (تیره‌تر)، `disabled` (opacity-50 + cursor-not-allowed) و `loading` (اسپینر + غیرفعال‌سازی).

### حالت‌های خالی / لودینگ / خطا
- **Skeleton**: کارت‌های شبیه‌سازی‌شده با انیمیشن shimmer هنگام لود لیست محصولات و صفحات.
- **Empty**: کامپوننت `EmptyState` واحد (سبد خالی، علاقه‌مندی خالی، بدون سفارش، بدون نتیجه جستجو).
- **خطا**: صفحه 404 اختصاصی + وضعیت خطای دریافت داده.

## ۴) تصمیم‌های UX

| تصمیم | دلیل |
|-------|------|
| کشوی سبد از **سمت چپ** (end در RTL) | استاندارد فروشگاه‌های ایرانی؛ با Escape، کلیک روی پس‌زمینه و قفل اسکرول |
| باز شدن خودکار کشو بعد از افزودن به سبد | بازخورد فوری — رفع مستقیم باگ اصلی گزارش‌شده |
| پرداخت ۳ مرحله‌ای با نوار پیشرفت | کاهش اصطکاک فرم‌های طولانی + اعتبارسنجی مرحله‌به‌مرحله |
| ارسال رایگان بالای ۵۰۰ هزار تومان + نمایش «سود شما از تخفیف» | شفافیت قیمت و انگیزه خرید |
| ورود سریع دمو (یک کلیک) | تست سریع جریان کامل برای توسعه‌دهنده و کارفرما |
| اعداد فارسی در همه‌جا (قیمت، تعداد، صفحه‌بندی، تاریخ) | نیاز بومی‌سازی RTL |
| فیلترها به‌صورت live اعمال می‌شوند + چیپ‌های فیلتر فعال | شفافیت نتایج و حذف آسان فیلتر |

## ۵) دسترس‌پذیری (a11y)
- `aria-label` برای همه دکمه‌های آیکونی، `role="dialog"` و `aria-modal` و `aria-labelledby` برای کشوها، `aria-pressed` برای قلب علاقه‌مندی، `aria-current` در صفحه‌بندی و مراحل، `role="alert"` برای خطاهای فرم، `role="status"` برای Toast ها، کنتراست کافی در هر دو تم، و فوکوس‌رینگ `focus-visible` روی همه عناصر تعاملی.

## ۶) کارایی
- **کد اسپلیت خودکار**: صفحات با `React.lazy` به chunk های جداگانه تقسیم شدند (بزرگ‌ترین chunk صفحه: ~12KB gzip).
- تصاویر محصولات با Pillow بهینه شدند (حداکثر 900px، JPEG کیفیت 82 — همه زیر 150KB).
- `loading="lazy"` برای همه تصاویر شبکه‌ها و `font-display: swap` برای فونت.
- لایه داده جدا (`services/api.js`) با تأخیر شبیه‌سازی‌شده — برای اتصال به API واقعی فقط همان دو تابع عوض می‌شود.
